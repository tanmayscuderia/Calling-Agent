**Subject:** API-tool dispatches silently die inside Samvaad executor — call force-ends (AGENT_ENDS), no failure recorded anywhere

**Severity:** High — broken production voice-agent behavior on ~30–40% of multi-tool calls

## 1. Summary

Between 2026-08-28 and 2026-08-29 we recorded repeated cases where an
API/HTTPS tool (GET) dispatch generated by the agent **never left Sarvam's
infrastructure**. The call then exhibits garbage output ("एक second, मैं check
करता हूँ। अरे, है क्या तू?") and is force-terminated with `ended_by:
AGENT_ENDS` within ~2 seconds — long before the tool's configured 5s max
wait. The tool's "If it fails" fallback message never plays. Sarvam's own
Attempts API reports `failure_reason: NO_FAILURE_REASON` and
`has_log_issues: 0` for these calls, while Sarvam's auto-generated call
summary on the dashboard simultaneously flags "the call ended abruptly with
an unprofessional remark from the agent."

We have since migrated our agent to a zero-mid-call-tool architecture
(on_start snapshot variables + on_end webhook only), which removes the
affected path for us — but the underlying executor behavior and the
telemetry blind spots remain a problem for any API-tool user, and we want
them fixed/acknowledged.
